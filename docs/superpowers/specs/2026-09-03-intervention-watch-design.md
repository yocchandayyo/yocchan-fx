1. 平均エンゲージメント時間（27秒からの変化）
2. 介入ウォッチページのPVと、そのページの平均エンゲージメント時間
3. 記事ページPV（トップ→記事の導線が食われていないか）

| データ | 取得元 | 更新頻度 | 備考 |

### 四半期遅れの扱い（重要）

日次データは四半期ごとの公表なので、**2026年7〜8月の介入が「どの日に」打たれたかは11月頃まで公表されない**。この期間について日別の内訳を推測して埋めることはしない。ページ上に「直近局面は月次合計のみ公表。日別内訳は◯年◯月公表予定」と明示する。

## 4. 警戒度スコア

0〜100点。算式はページ下部に全文を掲載する。「予想ではなく、過去の事実との距離です」と併記する。

### ① 水準距離（最大50点）

**基準線** = 直近に介入が確認された局面における、ドル円日足の最高値。

- 局面の期間は財務省の月次公表から特定する。**月次一覧のうち、介入額が0でない最も新しい期間**を採る（例: 2026-07-30〜2026-08-28）
- その期間の日足高値をYahoo Financeから機械的に取得する
- 円買い介入の期間のみを対象とする（円売り介入の局面は基準線に使わない）
- 人の判断は入らない

```
gap = 基準線 − 現在値（円）
gap <= 0    → 50点
gap >= 3.0  → 0点
それ以外    → 50 × (1 − gap / 3.0)
```

### ② ボラティリティ（最大25点）

```
r = 直近5営業日の平均日次レンジ ÷ 過去60営業日の平均日次レンジ
r <= 0.8  → 0点
r >= 1.5  → 25点
それ以外  → 25 × (r − 0.8) / 0.7
```

日次レンジは日足の high − low。

### ③ 当局者発言（最大25点）

`data/intervention_remarks.json` のうち、日付が直近10日以内のものを数える。

```
0件 → 0点 / 1件 → 8点 / 2件 → 16点 / 3件以上 → 25点
```

### 5段階表示

| スコア | 表示 |
|---|---|
| 0–19 | 低 |
| 20–39 | やや低 |
| 40–59 | 中 |
| 60–79 | やや高 |
| 80–100 | 高 |

メーターの下に3項目それぞれのバーと素点を出し、何がスコアを押し上げているかが分かるようにする。

## 5. ページ構成（上から順）

1. **警戒度メーター** — 5段階＋総合スコア＋内訳3本のバー
2. **次回公表までのカウントダウン** — 月次・日次それぞれの予定日と残り日数。月次は月末公表で日付が読めるが、**日次（四半期）の公表日は事前に確定しない**。直近実績（4〜6月期が8月7日公表）から「四半期末のおよそ6週間後」として推定し、ページ上に推定であることを明記する
3. **直近の介入実績** — 月次。期間・金額・過去比較（例: 月次で過去最大）
4. **当局者発言タイムライン** — 日付・人物・発言要旨・出典リンク（別タブ）
5. **過去の介入日とその後の値動き** — ドル円日足チャートに介入日をマーカー表示。マーカーにその日の介入額を出す
6. **算式と注記** — スコアの全算式、データ源、四半期遅れの説明、免責

  "score": {

## 8. 失敗時の動作

`update_intervention.py` は取得に失敗しても既存の `intervention.json` を壊さない。

- 取得できたブロックだけ更新し、失敗したブロックは前回値を保持する
- `source_status` に `ok` / `stale` / `error` を記録する
- ページ側は `stale` のブロックに「◯月◯日時点」と明示する
- スクリプトは失敗を標準出力に出し、朝の完了報告に警告として載せる

**数値を手で書き換えて埋めることはしない。** これはレートカードと同じ方針。

## 9. テスト

- `update_intervention.py` にセルフテストを持たせる。スコア3項目の算式について、境界値（gap=0 / 3.0、r=0.8 / 1.5、発言0 / 3件）で期待値どおりの点数が出ることを確認する
- 生成後に `intervention.json` のJSON妥当性と必須キーの存在を検証する
- 財務省CSVのパースは、行数と最新期の日付が想定範囲にあることを確認する（構造変更の検知）
- ブラウザで `intervention.html` を開き、コンソールエラーが無いこと、メーターとチャートが描画されること、ダーク／ライトいずれでも読めることを確認する
- ナビ追加後、全HTMLで導線が出ていることを確認する

## 10. コンプライアンス

- 「必ず」「絶対」「勝てる」等の断定・煽りを書かない
- 具体的な売買指示を書かない
- スコアは予測ではないことをメーターの直近に明記する
- 発言タイムラインは伝聞として書き、必ず出典リンクを付ける
- 取得元の記事本文をコピーしない
